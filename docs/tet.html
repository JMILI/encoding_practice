UDP 协议位域教程

一句话：线上传的是大端字节流，结构体位域按「声明顺序」从 bit0 往高位排， 小端电脑上必须先 ntoh 再读字段，否则会把 code 解成完全错误的数。

阅读顺序（建议从上到下）

  2. C++ 结构体怎么写 — #pragma pack(1) + 位域
  3. 两套坐标系 — 协议位号 vs 声明顺序
  4. data1 图解 — Canvas 看字节与位域
  5. data2 图解 — 4 字节同理

§1 报文长什么样

UDP 单播载荷按网络字节序（大端）依次发送：

type (1B) | len (2B) | fc (变长) | data1 (2B) | data2 (4B)
  • len = fc 字节数 + data1(2) + data2(4)
  • fc：从左到右编码；每字节最低位为续位标志（1=还有下一字节，0=结束）
  • data1 / data2：紧凑位域，#pragma pack(push,1)
示例报文：type=0x11, len=9, fc=51 73 B8, data1, data2（与实验台默认数据一致）

§2 C++ 结构体怎么写

位域成员谁先写，谁占低位（bit0 起）。与协议文档里「typeCode 在 15~13 位」的语义位号是同一回事，只是看图角度不同。

data1 — 2 字节

#pragma pack(push, 1)

// 声明顺序 = 从 bit0 往高位排：code → S3 → S2 → S1 → typeCode
struct Data1 {
    unsigned int code     : 10;  // bit 0 ~ 9
    unsigned int S3       : 1;   // bit 10
    unsigned int S2       : 1;   // bit 11
    unsigned int S1       : 1;   // bit 12
    unsigned int typeCode : 3;   // bit 13 ~ 15

    void hton() {
        uint16_t raw;
        memcpy(&raw, this, sizeof(raw));
        raw = htons(raw);           // 主机 → 网络大端
        memcpy(this, &raw, sizeof(raw));
    }
    void ntoh() {
        uint16_t raw;
        memcpy(&raw, this, sizeof(raw));
        raw = ntohs(raw);           // 网络大端 → 主机
        memcpy(this, &raw, sizeof(raw));
    }
};

#pragma pack(pop)

data2 — 4 字节

#pragma pack(push, 1)

struct Data2 {
    unsigned int feild_1     : 4;   // bit 0 ~ 3
    unsigned int feild_2      : 4;   // bit 4 ~ 7
    unsigned int feild_3      : 4;   // bit 8 ~ 11
    unsigned int feild_4      : 4;   // bit 12 ~ 15
    unsigned int sysCode : 16;  // bit 16 ~ 31

    void hton() {
        uint32_t raw;
        memcpy(&raw, this, sizeof(raw));
        raw = htonl(raw);
        memcpy(this, &raw, sizeof(raw));
    }
    void ntoh() {
        uint32_t raw;
        memcpy(&raw, this, sizeof(raw));
        raw = ntohl(raw);
        memcpy(this, &raw, sizeof(raw));
    }
};

#pragma pack(pop)

整条消息（示意）

struct UdpPayload {
    uint8_t  type;
    uint16_t len;      // 发送前 htons(len)
    uint8_t  fc[];     // 变长，此处略
    Data1    data1;    // 发送前 data1.hton()
    Data2    data2;    // 发送前 data2.hton()
};
记忆口诀：组包时各字段填好 → 对多字节整数 hton → 按字节顺序发出去； 收包时先 memcpy 进结构体 → 对 data1/data2 调 ntoh → 再读位域成员。

§3 两套坐标系：别搞混

角度怎么看举例（data1）
协议文档位号 从左往右标 bit16…bit1，像画在纸上 typeCode 占 15~13，code 占 9~0
C++ 声明顺序 从 bit0 往上长：先声明的在低位 先 code 再 typeCode
线上字节 大端：先传高字节 线上 0x31 0x42 表示 uint16 大端 0x3142
小端主机内存 ntohs 后得到数值 0x4231 再按 bit0 起拆位域
最大坑：把线上字节 31 42 的二进制直接当「小端 uint16」去拆位域 —— 会得到 code=322；正确做法是 ntohs(0x3142) = 0x4231，code=561。

§6 常见误区：322 vs 561

左：错误路径（不 ntoh）　右：正确路径（ntohs 后）
正确：ntohs(0x3142) = 0x4231 → code = 0x4231 & 0x3FF = 561（二进制 10 0011 0001）
错误：把 0x3142 当主机值 → 低 10 位 = 322（二进制 01 0100 0010） 
// 验证（小端 Linux / Windows）
uint16_t net = 0x3142;          // 模拟已 memcpy 进结构体、尚未 ntoh 的原始 ushort 视图
uint16_t host = ntohs(net);     // 0x4231
printf("wrong code = %u\n", net & 0x3FF);   // 322
printf("right code = %u\n", host & 0x3FF);  // 561
